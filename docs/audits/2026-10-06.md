# Research Bot audit — October 6, 2026

## Outcome and scope

Reviewed the shared backend, desktop/Android adapters, phone interface, persistence, authentication, network boundaries, assistant review, dependencies, updates, release automation and repository documentation. Confirmed problems were reproduced before correction where executable, and fixed with regression coverage. This review follows the maintainer's requested **“everything from top to bottom”** checklist, now captured in the [reusable audit skill](../../.agents/skills/research-bot-audit/SKILL.md).

Source baseline: `a80859449de82b23981b44ea161ab9e766061d72` on `origin/main`. Earlier uncommitted Android UI improvements were preserved and included. The resulting app version is **0.3.3**. The original MIT license and history are unchanged.

This is a repository audit using source review and the tools listed below. The Codex Security plugin's required support resources were unavailable, so its formal scan workflow was not run. No assertion is made that every possible bug or vulnerability has been found.

## Dependency decisions

The resolved dependency audit changed from **13 to 0 known vulnerabilities**. Overrides are intentionally limited:

| Parent / dependency                    | Resolution     | Compatibility evidence                                                                                                                              |
| -------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `concurrently` → `shell-quote`         | 1.9.0 → 1.12.0 | Existing command parsing remains compatible; the app scripts pass                                                                                   |
| `xcode` → `uuid`                       | 7.0.3 → 11.1.1 | Xcode uses `v4`; 100 generated identifiers are valid and unique. Version 11 retains CommonJS compatibility                                          |
| `@electron/get@3.1.0` → `global-agent` | 3.0.0 → 4.1.3  | The legacy downloader's `initializeProxy()` still bootstraps actual HTTP routing through a local proxy. This removes the `roarr`/`sprintf-js` chain |

Advisories: [shell-quote](https://github.com/advisories/GHSA-pqg4-j6r4-53mv), [uuid](https://github.com/advisories/GHSA-w5hq-g745-h8pq), [sprintf-js](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). No blanket forced major upgrade, suppressed advisory or older Electron/builder downgrade was used. Keep `test:toolchain` when updating these parents; upstream compatible dependency updates can eventually replace the overrides.

## Remaining limits

- Live ChatGPT eligibility, browser authorization and inference were not tested with the maintainer's real account. Grammar meaning/voice fidelity still needs real-output review.
- No physical OnePlus 7T Pro or Android emulator was connected. Legion OS background lifecycle, native Keystore/installer behavior and real soft-keyboard/browser callback flows need testing on the phone.
- Native loopback and APK verification were reviewed and compiled; they were not exercised against hostile traffic on a device. Public-link validation does not resolve DNS; source links are opened externally rather than fetched by a server.
- Local notes are not independently encrypted. Android saves are batched; the interface's saved indicator reflects the in-memory update before the snapshot reaches disk. Sudden termination before persistence remains a durability limit.
- macOS signing/notarization and Windows code signing are not configured. Local packaging validation runs on Linux; Windows/macOS packaging is covered by CI, not a local GUI run.
- The existing public release is unchanged. This source push does not configure GitHub signing secrets or publish a new binary release. Secret-list access was denied by the current GitHub integration, so present signing-secret configuration cannot be independently confirmed. Existing workflow failure evidence identified the missing Android key.
- A vulnerability scanner reports known patterns/advisories, not a guarantee of complete security. No speculative native parsing issue is included as a confirmed vulnerability.
