# Research Bot 0.3.7

This update fixes a reproduced Android sign-in compatibility bug: a WebView without `AbortSignal.any` could display `RB-AUTH-EXCHANGE-NETWORK` before sending its token request. Cancellation and deadlines now work through a compatibility fallback. Native DNS, TLS, timeout and connection failures retain safe, distinct error codes, and a failed sign-in shows the app and Android WebView versions for diagnosis.

Install the Android APK over your existing Research Bot app to keep projects and notes, then start a fresh sign-in. The APK uses the existing signing certificate and targets Android 16. Do not clear app data or reuse an old localhost callback URL.

Choose `mac-arm64.dmg` for Apple Silicon or `mac-x64.dmg` for an Intel Mac. The Mac app includes local research projects, autosaved notes, sources, plans, Markdown/JSON exports and assistants that require eligible ChatGPT access. Mac beta installers are ad hoc signed without Developer ID/notarization; updates are manual. [Mac installation and research guide](https://github.com/Srimi1/research------bot/blob/main/docs/macos.md).

The release pipeline tests native Android startup and saved-project recovery from the actual signed APK, and mounts, installs and runs each actual Mac DMG on its matching architecture before publication. Source CI also checks native HTTPS and a rejected dummy token exchange with the real Android bridge; synthetic browser fixtures cover identity validation and encrypted recovery. None of these uses a real ChatGPT account. Physical OnePlus/Legion OS behavior, live sign-in, eligibility and inference still need confirmation.

Checksums and Android build metadata are included in the release assets. See the [transport investigation](https://github.com/Srimi1/research------bot/blob/main/docs/audits/2026-10-07-android-auth-transport.md) for evidence and limits. If sign-in still fails, report only the fixed `RB-AUTH-…` message and displayed app/WebView versions; never share callback URLs, codes or tokens.
